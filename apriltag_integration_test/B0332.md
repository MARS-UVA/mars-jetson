# Arducam B0332 camera parameters

The [Arducam B0332 datasheet](https://uctronics.com/download/Amazon/B0332_OV9281_Global_Shutter_UVC_Camera_Datasheet.pdf)
specifies a monochrome global-shutter OV9281, native 1280×800 resolution, 3 µm square
pixels, a 2.8 mm M12 lens, nominal 70° horizontal FOV and distortion below 1%.
The published frame-rate table lists MJPG and YUY2 capture modes; recording/export
frame rate can differ from the sensor's supported capture rates.

`camera_b0332.yaml` is the shared active camera file for the three supplied recordings.
It uses these specifications directly, without fitting any of the test tag poses:

| Parameter | Value | Basis |
| --- | --- | --- |
| `fx`, `fy` | 933.3333 px | 2.8 mm focal length / 0.003 mm pixel pitch |
| `cx`, `cy` | 599.5, 399.5 px | Assumed centered optical axis in the 1200×800 recording |
| Distortion | Five zero coefficients | Approximation; the datasheet supplies only a <1% bound |
| Rotation | 180° | User's upside-down recordings |

The recordings decode at **1200×800**, whereas the nominal sensor is **1280×800**.
The current assumption is a centered crop removing 40 columns at each side without
resizing. This preserves focal length in pixels and shifts the native assumed
principal point from (639.5, 399.5) to (599.5, 399.5). If recording software instead
resized or otherwise cropped the sensor image, those parameters must be adjusted.
Resolution alone cannot determine what the recording software did.

The focal-length/pixel-pitch calculation implies approximately 68.9° native horizontal
FOV, close to the advertised rounded 70°. The focal-length/pitch values are the
chosen basis; the code does not mix the two approximate derivations or adjust them
to make the tag-distance results agree.

These are **manufacturer-specification estimates**, not a device-specific checkerboard
calibration. The datasheet does not supply measured `cx/cy` or `k1,k2,p1,p2,k3`.
Actual lens focal length, focus setting, optical-center shift, capture crop and
residual distortion can contribute to measured offsets. The metadata and CSV
`calibration_basis` fields preserve this limitation in exported results.

The active cases now use `analysis_mode: localization`, producing metric pose and
error columns through the actual installed `apriltag_ros` PnP implementation. All
three distances are scored against their supplied ground truth, including 1.0 m;
none is used to fit the camera parameters for this run.

After obtaining measured calibration for this recording mode, replace the numeric
intrinsics/distortion in the shared YAML and change `metadata.calibration_basis` to
`measured_calibration`. Keep the 180° rotation: the runner rectifies before rotating
and adjusts the published principal point consistently.
